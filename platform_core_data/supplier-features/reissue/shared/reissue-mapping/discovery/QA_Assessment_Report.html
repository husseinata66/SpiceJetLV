Method, gate, and recommendation

The question this scope answers is not whether reissue works. It is narrower: for every value on a reissue screen, does it still mean what the supplier meant?

  • Paired capture - supplier, core and screen read in one narrow window, because supplier prices move between calls.
  • Alignment by flight signature, never by array index - each layer calls Sabre separately and receives a different ordering, so offer[0] against offer[0] compares different flights.
  • The oracle: there is no design document; the implemented UI is the source of truth. A flag is raised only when a value comes back from the backend and is not displayed.
  • The platform never clicked Pay, Exchange or Confirm. Every payment was made by the human after the agent reported the exact flight and amount.
  • Querying the supplier directly is what found the worst defect. R13 was unreachable from any screen and any application payload. It is now a standing check for this scope.

A method failure worth recording: on 2026-09-29 a calculation error on scenario 5's confirmation was missed by the agent and caught by the user. The cause was not tooling - occurrences were being recorded without re-deriving the arithmetic behind them. The sweep that followed is what produced R02's root-cause correction.

Three findings were raised and withdrawn, and four claims were falsified by later evidence: R06's Critical escalation, R11's connection-point hypothesis, R12's multi-city hypothesis, and R15's wallet-is-correct claim. All are retained rather than deleted - a withdrawn finding is the record of what was checked.
