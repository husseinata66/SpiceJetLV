Defect Register
TC-BR-109 — A Branch assigns its suppliers to its Agencies instead of permitting them
Supplier NDCsbr with credential NDCSabre staging (313) was added to Branch BRN265. With no edit to Agency AGN9780, the Agency’s stored record returned that supplier as assigned, with credential 313 selected in its PCC tab; before the Branch change the same record held Sabre alone. A supplier and a GDS credential therefore reach an Agency without anyone deciding the Agency should have them, and the Agency’s Auto Reissue picker then offers a credential nobody chose for it. Re-executed as a controlled detach / re-attach: detaching the supplier from the Branch removed it from the Agency, and re-attaching it to the Branch alone put it back with its credential — so the Agency’s supplier set simply tracks its Branch’s, in both directions. PO-27 makes the Branch a ceiling, not a source of assignment. Full write-up: ManualExecutionResults.md §3.1.
TC-AGENCY-092 — An inactive credential is still offered in the Agency picker
With credential NDCSabre staging Inactive, the Agency’s saved selection correctly dropped it and Auto Reissue stayed ticked, but the picker still offered it. The Branch screen, in the same window, correctly hid it. run-006 found the same behaviour and the user decided on 2026-09-26 that it is intended, because the API refuses the save — but that decision was never written into the case, so the approved Expected Result still says “not offered” and this execution must record a failure. Reproduced in a second, independent inactive window with the same result. The fix belongs in Stage 3. Full write-up: ManualExecutionResults.md §3.1.
TC-BR-107 — A created Branch does not keep the Auto Reissue setting it was created with
Executed twice. Branch BRN514, then BRN515 on a re-run that completed the cascading location fields first, were each created (POST 204) and approved, and each reopened with Auto Reissue unticked and no Product Access supplier. On the re-run the live form was read from the DOM immediately before submitting and showed Auto Reissue on, Auto Reissue Credentials GalileoLive, and Galileo ticked — which removes the form-model reset that left the first attempt Inconclusive. A Branch created with Auto Reissue on silently does not have it, and is approved in that wrong state. Editing a Branch afterwards saves correctly, so the fault is confined to the create path. Full write-up: ManualExecutionResults.md §3.1.
