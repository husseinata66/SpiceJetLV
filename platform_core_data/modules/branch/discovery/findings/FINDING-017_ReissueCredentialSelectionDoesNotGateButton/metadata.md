# FINDING-017 — The Reissue button shows even when the booking's credential isn't among the selected Auto Reissue Credentials

- **Finding ID:** FINDING-017
- **Title:** The Reissue button shows even when the booking's credential isn't among the selected Auto Reissue Credentials
- **Category:** Observation
- **Severity:** N/A
- **Severity Reason:** The user confirmed this as intended (`PO-22`): the checkbox controls only whether the button shows, and the selected credentials are enforced when Reissue is clicked. No Severity Matrix criterion applies to confirmed intended behaviour.
- **Confidence Score:** 95%
- **Evidence Category:** Direct Observation
- **Status:** **Rejected — Confirmed Intended Behaviour** (user, 2026-09-24, `PO-22`)
- **Business Risk:** None to the application. A tester could expect the button to be hidden for a booking on an unselected credential, and write a wrong expected result. The real refusal (*"No credential for this booking is assigned to your organisation"*) happens after Reissue is clicked, in scope `reissue-flow`.
- **Technical Risk:** None identified. `canAutoReissue` doesn't include the credential selection, so it can't be used alone to test that selection.
- **Module:** branch
- **Workflow:** Admin → Branch → edit BRN265 → Auto Reissue on/off → Approve → `/booking/search-booking` → Flight → `NDCEG-BR-F260916ENYOeQ` → Itinerary (lock held) → passenger panel
- **Description:** Booking `NDCEG-BR-F260916ENYOeQ` (order `BRN265NDCORD2609169XJ1LC`) was made by the user under Branch BRN265 itself. Its agency is `null`, the supplier is **Sabre** and the credential is **315 "Sabre Staging"**. BRN265's saved Auto Reissue Credentials were **[313 "NDCSabre staging"]** (NDCsbr) only. With BRN265 **on**, the booking showed **Reissue** (`canAutoReissue: true`). With BRN265 **off**, it didn't (`false`). The button followed the Branch's checkbox and ignored whether 315 was selected.
- **Expected Behavior:** Branch ProjectContext §1.2 `PO-22` (added during Stage 2): *"The checkbox controls only whether the `Reissue` button is shown. The selected Auto Reissue Credentials are enforced only when **Reissue** is clicked … Seen on BRN265: a booking on 315 shows the button while BRN265's selection is only 313 — expected."* Before `PO-22`, spec §5 listed three conditions (Booked, the organization's auto-reissue on, supplier allowed) and said nothing about the selected credential. Branch ProjectContext §3 had also excluded Branch-created bookings unless Stage 2 showed they exist (ASM-BR-6). See the QA report §11 `GAP-BR-R6-02`.
- **Actual Behavior:** In one browser session, with the flag read just before each check (`33-branchbooking-cycle-results.json`): 10:27:29 UTC BRN265 `autoReissueEnabled false`, `[313]` → 10:27:37 `canAutoReissue false`, no Reissue. 10:28:24 `true`, `[313]` → 10:28:30 `canAutoReissue true`, **Reissue shown**. Manual Reissue showed both times. The booking was locked (`locked 1`).
- **Steps to Reproduce:** 1) On `/admin/branch/edit/…` for BRN265, set Auto Reissue **on**, keep only "NDCSabre staging" selected, then Remarks → Send For Approval → approve. 2) Open booking `NDCEG-BR-F260916ENYOeQ` from Search Booking → Flight, take the lock, and open View Passenger Details. 3) See **Reissue**, even though the booking's credential (Sabre Staging) isn't selected. **Do not click it.** 4) Turn BRN265 **off** and approve. The button disappears.
- **Investigation/Recovery Result:** Not applicable (no failure category). There was one confound, then a re-check. A first OFF check (10:24:52 and 10:25:47) showed `canAutoReissue true` because BRN265 had been switched back on by hand in another session at the same time (the user confirmed this). It was discarded as inconclusive and repeated in one session, with the flag read right before each button check (10:27–10:28). Only the repeated cycle counts as evidence.
- **Investigation Notes:** **Second occurrence (agency side):** on the Portal cycle, AGN9780 was saved **on** with Auto Reissue Credentials **[277 "GalileoLive"]**. At that time the picker offered only GalileoLive, after the user's manual changes to AGN9780. Booking `NDCEG-BR-F260924EAzzYT` is on **Sabre Staging**, and it still showed Reissue on the Portal (`43-portal-cycle-results.json`, 13:11:56 and 13:12:47). **Also seen:** BRN265 gained supplier **Sabre** (315 checked, 297 unchecked) during the run through the user's manual change (confirmed 10:24). It is recorded in `05-BRN265-baseline-before-changes.json` (`laterChangeOutsideRun006`). **Not tested:** clicking Reissue to see the refusal message, which is out of scope here and never clicked.
- **Occurrence Count:** 2 (BRN265 Admin cycle; AGN9780 Portal cycle)
- **Evidence Links:** `33-branchbooking-cycle-ON.png` (Reissue shown, BRN265 on), `33-branchbooking-cycle-OFF.png` (hidden, BRN265 off), `33-branchbooking-cycle-results.json` (flag before/after and the button, per step), `45-itinerary-credential-fields.txt` (both bookings: supplier Sabre, `ticketPccId = 315`; Branch booking `agencyId null`), `05-BRN265-baseline-before-changes.json` (BRN265 selection [313], with the note on the later Sabre supplier), `43-portal-cycle-results.json` (the agency-side occurrence). Originals also in `runs/run-006…/discovery/evidence/`.
- **Recommendation:** No action is needed on the application. For Stage 3, the checkbox cases assert the button only. The "credential not selected → refusal" case belongs to `reissue-flow` (`Reissue_Flow_From_Itinerary.md` CL-1).
